## Step 1: [Manual] interpret-bytecode

> Write an AST + pretty-printer + interpreter for OCaml bytecode; ~150 instructions, ~1500 LoC

Location: manual/

Files:

- manual/Utils/AST.v (107 lines) -- Defines the instruction type with 107 variants (ACC, PUSH, CLOSURE, BRANCH, ADDINT, C_CALL, etc.), one-to-one with OCaml's opcodes.h. This is the bytecode AST.

- manual/Utils/Value.v (52 lines) -- Runtime value representation: Val_int (integers), Val_block (tagged tuples/data), Val_ptr (heap pointers), Val_closure (closures). Also defines val_unit, val_true, val_false, and decidable equality.

- manual/Utils/Syntax.v (58 lines) -- Source-level OCaml AST: 14 expression forms (int, bool, if, let, letrec, fun, app, match, tuple, constructor, seq), 7 pattern forms, 4 declaration forms, type expressions. This is the source AST that the pretty-printer targets.

- manual/Utils/Observable.v (29 lines) -- Defines what a program's observable behavior is: a list of Out_char events (stdout trace) plus a termination (normal with value, error with message, or timeout). This is what the correctness theorem equates.

- manual/InterpBytecode/Machine.v (109 lines) -- The ZINC machine state: program counter, accumulator, stack, environment, extra_args (for partial application), global data array, trap stack (for exceptions), mutable heap, and next free address. Also defines step_result (Step/Halt/Error/CCall_request) and run_result.

- manual/InterpBytecode/Interp.v (831 lines) -- The core trusted component. A step function with one case per bytecode instruction (~100+ match arms), faithfully modeling OCaml's runtime/interp.c. Handles closures, partial application (GRAB/RESTART), exception handling via trap stack, mutable heap ops, 63-bit signed arithmetic. run wraps step in a fuel-based loop with C-call callback support.

- manual/InterpBytecode/Encode.v (321 lines) -- Bytecode encoder: takes a list of instruction and produces a list of bytes (little-endian 4-byte words). Two-pass: first computes instruction sizes to build an offset map, then emits words, converting absolute instruction indices to relative branch offsets. Always uses general opcode forms (e.g. ACC=opcode 8, never ACC0-ACC7).

- manual/InterpBytecode/Loader.v (550 lines) -- Bytecode decoder: the inverse of the encoder. Takes raw bytes, parses them into (opcode, operands) pairs, then resolves relative branch offsets back to instruction indices using a word-offset map. Also parses the .cmo file format (section table at EOF with CODE/DATA/PRIM sections).

- manual/InterpBytecode/WellFormed.v (68 lines) -- Decidable well-formedness check: verifies all numeric operands fit 32-bit, all branch targets are valid instruction indices, and SWITCH/CLOSUREREC sizes match their operand lists. Returns bool.

- manual/InterpBytecode/LoaderCorrectnessSpec.v (21 lines) -- Module Type specifying the roundtrip theorem: forall code, well_formed code = true -> decode(encode(code)) = code. This is the contract the automatic proofs must satisfy.

- manual/InterpBytecode/IO.v (150 lines) -- Opaque axioms with Extract Constant directives that bridge Rocq to the OCaml runtime: read_file, print_string_io, sys_argv, marshal_from_bytes, unmarshal_globals, load_primitives. Each axiom has an explicit OCaml extraction body.

- manual/InterpBytecode/Main.v (319 lines) -- Standalone entry point. Reads a bytecode file, parses CODE/DATA/PRIM sections, builds a C-call handler dispatching ~20 primitives (print_int, string ops, comparisons, etc.), initializes machine state, and runs with 100M fuel.

- manual/Checker/LoaderCorrectnessChecker.v (10 lines) -- Module Check <: LoaderCorrectnessSpec. Rocq type-checks that the automatic loader proofs satisfy the manual spec.

## Step 1.1: [Auto] PBT harness

> PBT harness to verify that ocamlrun and interpret-bytecode do the same thing

Location: automatic/test/interpret-bytecode-pbt/

Files:

- harness.ml (314 lines) -- QCheck property-based test with 37 generators (arithmetic, closures, recursion, pattern matching, refs, strings, loops, etc.) x 200 iterations. For each generated OCaml program: compiles with ocamlc, runs with ocamlrun for expected output, then loads the same bytecode through our interpreter and compares. Uses a native OCaml run loop (bypasses extracted nat overhead) with 10M step limit.

- manual_test.ml (82 lines) -- 4 hand-crafted bytecode tests: simple arithmetic (3+4=7), function call (closure + APPLY1), global variable set/get, and block (pair) field access.

- trace.ml (130 lines) -- Debugging utility. Takes a .cmo file and prints a per-step execution trace: instruction, PC, stack depth, accumulator value.

- ocaml_testsuite_runner.ml (156 lines) -- Runs OCaml's own test suite (from automatic/test/ocaml-testsuite/basic/) through our interpreter with a 5-second wall-clock timeout per test. Prints a pass/fail/skip summary.

Shared infrastructure (used by this step and all subsequent test steps):

- automatic/test/common/test_common.ml (205 lines) -- Core utilities: compile_and_run_ocamlc (compile source, run with ocamlrun, return output), make_handler (C-call dispatch for ~35 primitives), obj_to_value (convert OCaml Obj.t to our value type), load_globals/load_prims (parse DATA/PRIM sections), run_our_compiler (compile AST + interpret bytecode), run_ocamlc_bytecode (load ocamlc output + interpret).

- automatic/test/common/loader.ml (224 lines) -- OCaml-side bytecode loader. Mirrors manual/InterpBytecode/Loader.v but in native OCaml. Parses .cmo format, decodes opcodes, resolves branch targets.

- automatic/test/common/interp_extracted.ml (~5000 lines, generated) -- Auto-generated by make extract. Contains OCaml code extracted from all Rocq theories. Do not edit.

## Step 2: [Auto] lex-parse + [Semi-auto] pretty-printer

> Process OCaml source into AST + pretty-printer reverse direction

Location: automatic/test/compile-pbt/ (lex-parse) + semi-auto/Compile/LexParse/ (pretty-printer)

Files:

- automatic/test/compile-pbt/lexer.ml (99 lines) -- Tokenizer for the OCaml subset. 23 token types (INT, STRING, keywords, operators, punctuation). Single-pass state machine handling nested (* *) comments, identifiers, integers, and operators.

- automatic/test/compile-pbt/parser.ml (311 lines) -- Recursive descent parser for fully-parenthesized OCaml source. Parses expressions, patterns, types, and declarations. Assumes input is perfectly parenthesized (from the pretty-printer), so no precedence handling is needed.

- semi-auto/Compile/LexParse/PrettyPrint.v (108 lines) -- Rocq pretty-printer: converts AST back to a fully-parenthesized OCaml source string. Deliberately simple -- every expression is wrapped in parens for unambiguous roundtripping. This is the "trusted direction" because it's a simple injection. Has a length penalty as a semi-auto constraint.

- automatic/test/compile-pbt/roundtrip_test.ml (269 lines) -- Parser roundtrip PBT. Generates random ASTs, pretty-prints them via PrettyPrint.v, parses back via lexer.ml+parser.ml, and checks equality. 500 expression + 100 declaration iterations.

## Step 3: [Auto] compile + [Auto] interpret

> compile (using lex-parse) and interpret

Location: automatic/theories/Compile/ (compile) + semi-auto/Interpret/ (interpret)

Files:

- automatic/theories/Compile/Compile.v (401 lines) -- Compiler from source AST to bytecode instruction lists. Handles closures (with free variable analysis), recursive closures (CLOSUREREC), pattern matching with backtracking, tuples (MAKEBLOCK), let/letrec, binary ops, if/else, and built-in function inlining (print_int, fst, snd). Uses fuel for termination. Maintains a compilation environment mapping identifiers to stack/environment/self locations.

- semi-auto/Interpret/SourceInterp.v (357 lines) -- Fuel-based direct AST evaluator. Defines source values (svalue: ints, bools, tuples, closures, constructors, builtins), environments as linked lists, and a recursive eval function. Pre-loads stdlib with 7 builtins (print_int, print_string, print_newline, print_char, compare, fst, snd). This is the specification of what programs mean. Has a semi-auto length penalty -- kept short because the correctness theorem relies on it.

PBT for this step:

- automatic/test/compile-pbt/compile_test.ml (305 lines) -- 32 generators x 200 iterations. For each generated (AST, source) pair: compiles source with ocamlc + runs with ocamlrun for expected output, then compiles AST with our compile_program + runs through our bytecode interpreter, and compares.

- automatic/test/interpret-pbt/source_interp_test.ml (197 lines) -- 16 generators x 50 iterations. For each generated (AST, source) pair: compiles source with ocamlc + runs with ocamlrun for expected output, then interprets AST directly with interpret, and compares.

## Step 4: [Manual] Correctness theorem + [Auto] Proof + [Semi-auto] interpret penalty

> Define the compiler correctness theorem. Continue to prove theorem. Impose a penalty for interpret length.

Location: manual/Correctness/ (theorem definition) + automatic/theories/Correctness/ (proof) + manual/Checker/ (verification)

Files:

- manual/Correctness/CorrectnessSpec.v (27 lines) -- Module Type declaring the correctness interface. Parameters for compile_program, interpret, and compiler_correct. Axiom: compiler_correctness -- states that all programs satisfy the correctness predicate. This is the trusted statement of what correctness means.

- automatic/theories/Correctness/CorrectnessProofs.v (119 lines) -- States the actual theorem: if interpret terminates normally with trace T, then there exists enough bytecode fuel such that compile -> run_bytecode produces the same trace T. Defines ccall_to_events (maps primitive indices to output events), run_collecting (accumulates bytecode output), and bytecode_behavior. Main theorem is Admitted -- proof to be filled in as compile/interpret evolve.

- automatic/theories/InterpBytecode/LoaderCorrectnessProofs.v (189 lines) -- Roundtrip proof for encode/decode. Helper lemmas for byte-level operations are proved. Main theorem decode_encode_inverse is Admitted (4 key lemmas still admitted around Z bit-manipulation and offset map reasoning).

- manual/Checker/CorrectnessChecker.v (15 lines) -- Module Check <: CorrectnessSpec. Rocq type-checks that the automatic proofs from CorrectnessProofs.v satisfy the manual spec.

- manual/Checker/LoaderCorrectnessChecker.v (10 lines) -- Module Check <: LoaderCorrectnessSpec. Same pattern for the loader roundtrip.

The semi-auto interpret penalty (line 16 of content.txt) is a constraint on semi-auto/Interpret/SourceInterp.v -- the source interpreter is penalized for being long, with the penalty amplified if the LLM can't find a program where the previous interpret and ocamlrun/ocamlc disagree. This incentivizes keeping the interpreter simple and correct.

## Top-level infrastructure

- Extract.v (51 lines) -- Extraction configuration. Lists ~50 definitions to extract from Rocq to OCaml (value types, instruction type, step/run functions, compiler, interpreter, pretty-printer, encoder/decoder, standalone main). Output goes to automatic/test/common/interp_extracted.ml via make extract.

- Makefile -- Orchestrates: build (dune builds all Rocq theories) -> extract (coqc produces interp_extracted.ml) -> test (runs all 6 PBT executables).

- dune-project -- Dune 3.16 with Coq 0.8 plugin, project name ocaml_bytecode_interp.
